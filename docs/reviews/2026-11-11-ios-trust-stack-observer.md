That passing result does not repair or explain the earlier initial-pairing or post-relaunch failures. Their raw logs, annotations and result bundles remain separate retained evidence. The new diagnostic is for collecting app/trustd stacks during a future stalled interval before teardown; it is not a TLS repair or native acceptance result.

## Collection and authority

`Scripts/test-e2e.sh` starts the observer only for an explicit Debug CI run on macOS with a selected simulator UUID. The helper verifies that exact device is booted. Existing DEBUG opt-in phase records are bound to the currently installed Companion image in that device, numeric UID, process start metadata and the OS log's process/boot identity. Security activity must match the same app thread and follow the callback's chain-start before a same-boot trustd peer can be correlated. Process metadata is rechecked immediately before sampling, and the captured sample header must match the target PID and expected process-birth second. These are metadata spot checks, not atomic task-port identity or PID-reuse exclusion.

After chain-start has lacked a return for at least five observed seconds, collection is limited to two stalled callbacks and at most four one-second stacks. Completed callbacks suppress pending collection; observer shutdown aborts its own operations. Each subprocess has a bounded deadline, output cap, TERM/KILL escalation and a final bounded wait. Log windows, active/unique observers, refusal records, output files and overall observation time are bounded. An unconfirmed command close records its PID/code, stops observation and prevents every adapter from launching another command. Direct command closure does not prove simulator-side descendant cleanup.

The paired shell harness stops only helpers still present in its own running-job table, uses bounded escalation and retains Xcode's original exit status. No target app or trustd process is terminated by the observer. Stack files use exclusive creation inside an owned private artifact directory; diagnostic commands inherit a minimal environment. The manifest explicitly retains unavailable collection and cleanup uncertainty. Nothing converts missing diagnostics into a passed test. Simulator log queries and sampling may affect scheduling; this instrumentation does not establish unaffected runtime timing.

No Swift/client source, Security API, pin comparison, redirect refusal, request deadline, test assertion, model, provider, inference policy or product admission is changed. Hosted operation and native acceptance require their own fresh evidence.
