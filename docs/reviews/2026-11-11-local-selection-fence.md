# Hold a draft until its local destination is pinned

## Demonstrated failure

Final whole-branch review of `aa095b29ff310bd837cdf6aac6af9389c122e9af` found that `chooseLocalForDraft` created a thread asynchronously without reserving its source draft. While creation waited, the original composer could accept text and admit a send using its previous non-local configuration. This remained reachable when normal product admission would later refuse the local target. Successful fixture admission also hid intervening input instead of transferring it.

Two controlled Electron regressions reproduced the failure through the production renderer, preload, store and IPC. Only the first creation reply was held. Final send dispatch was intercepted before any provider ran. Both the ordinary gated build and admitted scripted fixture cleared the expected original draft and reached native begin plus final-send boundaries while local creation remained held. Those two boundary calls describe one attempted message pipeline, not two model turns. No real cloud/model request was made. The first fixture rejected native begin too early, producing held-recovery teardown/dialog errors; its original traces and assertions remain retained. The corrected fixture preserves native begin/transfer and returns a normal failed final-send result, yielding two direct input-preservation assertion failures without that teardown setup problem.

## Repair

The renderer rechecks the current source identity, text and attachment state before local selection. It synchronously reserves the empty source and records a key-specific input/send fence before its first await; after creation the prospective target receives the same fence before pinning. Text, settings and staging callbacks recheck those keys, so a stale event cannot bypass the visible inert composer. The existing native/browser send paths refuse the held key. This is a renderer lifecycle fence, not a new execution admission or credential privilege.

Only the source and prospective target views are inert. Navigation, unrelated composers and Stop remain available. On success the exact original raw buffer, including whitespace, moves to the pinned thread and is selected only if its source is still active. Refusal leaves the original draft intact and removes the failed empty target through the existing path. A finally block releases both keys and the empty attachment reservation; the failure wrapper does not automatically retry the inner create/pin operation. Production LocalExecution remains unadmitted and native/client permissions are unchanged.
