# Desktop v0.0.4 release review

The release scope is reviewed main after [PR #35](https://github.com/TypeSafeAI/modex/pull/35) (threads name themselves) and [PR #36](https://github.com/TypeSafeAI/modex/pull/36) (one suggested next step). Desktop v0.0.3 was the previous release. The distribution remains macOS Apple Silicon, ad-hoc signed and not notarized. The monorepo and core package keep their existing versions.

This review extends the [v0.0.3 release review](2026-09-28-v0.0.3-release-review.md). Unlike the two patch releases before it, this one adds behaviour rather than fixing it: both features run a small piece of model work outside the coding turn, and the review concentrates on what leaves the process and what can never enter the transcript.

## What changed

| Area | Change and regression evidence |
| --- | --- |
| Thread titles | A new thread still takes its opening message as its title immediately. Once the first turn completes, the thread's own CLI runs a separate, non-resumed chat turn in a temporary directory asking only for a 3–8 word title; approvals in that turn are answered "no", and multi-line or over-60-character answers are discarded. The title is written only while the first-message title is still in place, so a manual rename wins; rename, deletion and app quit abort the request, a 30 s timer bounds it, and quit waits for an in-flight request to settle. The mock backend has no naming, so demos and e2e are unchanged. Unit tests cover the isolated turn, the normalisation, cancellation on rename and delete, and shutdown waiting. |
| Follow-up suggestion | After a completed turn the composer shows one suggested next message as a ghost line on the empty input. Click, Tab or → fills it; sending stays a separate keystroke; anything typed hides it. The candidates are six fixed strings in `routing/followup.ts`, so the judge can only pick a key or `none`; nothing it says becomes prompt text. Jev is asked only on Auto threads, with routing's confidence floor, and sees only typed facts about the turn (request, task kind, plan/mode, and whether tools edited files, ran checks, failed, or the answer mentions remaining work). Assistant text, tool arguments and tool output stay local, asserted by a unit test that plants private markers and checks the outgoing request. Non-Auto threads, an offline judge, a low-confidence or unknown answer, and every error fall back to a deterministic rule. The runner caches one answer per transcript state and clears it on send or Stop; a turn that ended in an error or a Stop offers nothing. The composer box keeps its 98 px rest height (layout references unchanged). The main-flow e2e asserts fill on Tab, → and click, no self-send, and that a typed draft is never replaced. |
| Layout e2e | The terminal-panel geometry check now waits for the panel's 180 ms enter animation to settle before comparing its bottom edge to the main pane. CI had measured 2–3 px of transient offset on one of two runs of the same commit. |
| Docs | `docs/status.md` records what has shipped, what is on main but unreleased, in-flight work and what is next; `AGENTS.md` points to it. `docs/auto-routing.md` describes the follow-up question. |

## Findings

| # | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | Medium | The first cut of the suggestion added a row inside the composer, growing it past the 98 px reference and shifting every control below it. | Rendered as a ghost line over the input's first line instead; the placeholder attribute is unchanged and hidden only visually. Layout e2e green. |
| 2 | Low | Title generation is a real CLI turn and could, in principle, act on the opening message. | The prompt marks the message as data, the turn runs in chat mode with plan off in an empty temporary directory, approvals are refused, and only a short single-line answer is accepted. |
| 3 | Low | The renderer asks for a follow-up on every render of an idle thread. | The runner caches per transcript state (last item id, plan, mode, auto), so Jev is asked at most once per completed turn. |

## Verification

Checked on macOS 26.6.2, Apple Silicon, Node 24:

- Build and TypeScript checks passed.
- 132 unit tests passed: 15 core and 117 desktop, including 5 for titles and 7 for follow-ups.
- 57 Electron end-to-end tests passed from source and again against the packaged application, using isolated homes and temporary repositories.
- The packaged app reports version 0.0.4 and arm64 architecture. `codesign --verify --deep --strict` passed with an ad-hoc signature; DMG and ZIP integrity checks passed.

Run the source checks from a worktree:

```sh
npm run build
npm test
npm run typecheck
npm run test:e2e
```

Build and exercise the actual bundle:

```sh
npm run dist -w @modex/desktop
MODEX_PACKAGED_APP="$PWD/apps/desktop/release/mac-arm64/Modex.app/Contents/MacOS/Modex" npm run test:e2e
codesign --verify --deep --strict --verbose=2 apps/desktop/release/mac-arm64/Modex.app
hdiutil verify apps/desktop/release/Modex-0.0.4-arm64.dmg
unzip -tq apps/desktop/release/Modex-0.0.4-arm64.zip
```

## Proof limits

Offline scripted CLI tests do not establish live-provider execution, paid-model behaviour, or human VoiceOver acceptance. In particular, neither the quality of generated titles nor Jev's follow-up choices are exercised here: the mock backend does not name threads, and the e2e runs without a key, so every suggestion in the suite came from the heuristic. Title generation costs one small model call per new thread on Claude and Codex. This release does not add notarization, a custom app icon, auto-update, or Windows/Linux installers.
