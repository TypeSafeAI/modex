# v0.5.0 candidate review: Code Review on by default (2026-11-04 goal, run 2026-11-12)

**Draft. It waits for Val and is not for the merge queue.** PR #515, branch `cr-default-on`. No human gate has run on it.
It supersedes the [2026-11-02 candidate](2026-11-02-v0.5.0-candidate.md).

## What it is

The tested commit is `683ab6eccaf31310a7a4e0fb465077d243c02a06`: `main` at `3691bc5` merged into the real-use fixes
(#506, then #513 on top of it, neither merged yet) plus one change: `DEFAULT_LAYOUT.codeReview` is `true`.

- Built and development apps show Code Review in the rail on a fresh home.
- Rollback: Settings → General → "Show Code Review in the rail". A saved choice to hide it is kept, and the old
  `modex.codeReview` switch is still migrated.
- The Store build and the browser demo pass `codeReviewEnabled={false}` and never show it.

The code and tests come from the uncommitted work in the v0.4.2 recovery worktree. That work's README and v0.4.2
release-review edits are not included.

## The one full run

`pnpm build && pnpm test && pnpm test:e2e`, once, no reruns, on 2026-11-12 from 16:03 to 16:25 UTC (load average 7.9
at the start).

| Step | Result |
| --- | --- |

| `pnpm test` | passed: 2,579 tests in six runs, 2,543 passed, 36 skipped, 0 failed |
| `pnpm test:e2e`, desktop | **failed: 534 tests, 522 passed, 11 skipped, 1 failed** (18.8 minutes) |

**The failure.** `e2e/code-review-enablement.spec.ts:19`, "Code Review is visible by default without a switch, stays
idle until opened, and survives a reload". Every step about Code Review passed. The last check, added with the
default-on change, required that no provider CLI had started at all. Three had: `codex --version`,
`codex app-server` and `claude --version`. Those are the app's own checks of its installed CLIs, not model turns
and not Code Review.

**After the run** (commit following `683ab6e`; these are not part of the one run):

- The check now requires that no model turn started (`claude -p` or `codex exec`), which is what it was written to
  prove. This changes an assertion that was new in this candidate and had never passed. The spec then passed alone,
  3 of 3.
- The two suites the command never reached were run once each: site 8 of 8, browser demo 4 of 4.
- No second full run was made.
