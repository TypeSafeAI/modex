# v0.1.0 release review

Desktop v0.1.0 is the first minor release. Space notes become Markdown files in a folder of
workspaces, projects and folders, and each Modex project gets its own notes that its agents
stay inside. It also adds Images and native Plugins, a usage Analytics surface, and thread
archiving. Val chose on 2026-10-15 to include Images and Plugins (#236).

This preparation starts from protected `main` at `4408c9c515bc8a5c899d047851bf720be4e96298` (#243). It changes only the
desktop version and the release records.

## Candidate behavior and compatibility

- **Notes migration.** The first launch of 0.1.0 moves Space pages from the old store into
  Markdown files under `MODEX_HOME/notes` (#222). Each existing project gets its notes project
  the first time notes open. Removing a project keeps its notes.
- **Agent scope.** A project's Pages and Knowledge agents see only that project's notes. If the
  notes folder cannot be read, the turn keeps running and Pages refuses with the reason; it
  never runs unscoped.
- **Updates.** v0.0.12 is the first self-updating build, so 0.1.0 is the first
  published-to-published automatic upgrade. The hosted updater scenarios use a private
  `0.0.0` fixture built from the same source; they do not prove an upgrade from the published
  v0.0.12 build. That upgrade gets a manual check after publication (see
  [Release gates](#release-gates)).
- **Platforms.** The macOS arm64 build is Developer ID signed (Soul Protocol LLC) and notarized
  by the Release workflow. The workflow also produces Windows and Linux candidates. Whether
  those are published is decided at publication, as it was for v0.0.12.

## Review

A pre-merge review of the combined notes stack found seven main-process and five renderer
defects. Three were fixed before landing in #227:
- Agent turns failed in every project when the notes folder could not be read.
- **Open notes** re-focused on every poll.
- Tree layout was quadratic: 9,900 files took 21–51 s per layout and now take about 0.25 s.

Codex's review of those fixes found a fail-open for exceptions with no message and a focus
replay after remount. Both were fixed in #227 with regressions. Nine lesser findings are
tracked in #241.

## Release gates

1. Land this preparation through the guard, then sign tag `v0.1.0` on its squash.
2. The Release workflow, after `release-signing` approval:
   - signs, notarizes and staples the app and DMG, then runs the packaged E2E;
   - runs the three hosted native updater scenarios and the Windows and Linux checks;
   - attaches the candidates to a draft.
3. Download the draft's assets and verify them independently:
   - `shasum -c`, the codesign leaf, `spctl` for the app and the DMG, and `stapler`;
   - the packaged E2E against the downloaded app.
4. Publish, then check `releases/latest` with the shipped updater parser.
5. Upgrade a v0.0.12 install through its own updater, and record the result.

## First tagged run

Signed tag `v0.1.0` on `17f8e52` (#244) started [run 38803510045](https://github.com/TypeSafeAI/modex/actions/runs/38803510045).
Signing, notarization, stapling and the packaged E2E passed, as did the Windows and Linux candidates and
all three signed native updater scenarios. The last job, "attach verified release artifacts", failed in
`actions/setup-node@v5` with `Unable to locate executable file: pnpm`. setup-node v5 caches the
`packageManager` named in `package.json`, which has been pnpm since #196, and that job never installs
pnpm. No draft was created. #251 turned the cache off for that job. A rerun would use the tag's own
workflow, so the unpublished tag was replaced, as for v0.0.12.
