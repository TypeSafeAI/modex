# v0.0.11 release review

Prepared on 2026-10-12. This release follows v0.0.10 and carries everything that landed on
`main` since: sticky Auto routing (#180, #183), the minimal right workspace rail (#178),
Companion on multiple networks and Store host recovery (#166), Windows and Linux installer
candidates (#173), worktree hygiene, composer attachments, usable Streamer Mode, browser
extensions with document-bound 1Password filling (#152), and the Graphite reference layout.
The [status page](../status.md#v0011-release-candidate) lists each change with its own evidence.
iPhone companion build 6 is cut from the same source.

## Scope and compatibility

The published artifacts are macOS Apple Silicon only, as for every release so far. Windows
and Linux installers remain Actions candidates; publishing them is a separate `Next` item.
`state.json` gains an optional `lastTurn` per thread and `routing-fit.json` records gain
optional cache fields; older builds ignore both. Auto routing changes behavior on threads with
a CLI session: it keeps the model while the prompt cache is likely warm (see
[auto-routing.md](../auto-routing.md), step 7).

Mac App Store and iPhone distribution remain separate tracks. Physical iPhone and human
VoiceOver acceptance were not performed for this release.

## Hosted check failures during landing

- **Store browser menu test** (`workspace-store.spec.ts:8`). The hosted macOS push runs of
  both #180 (run `38213501661`) and #183 (run `38216813841`) failed at the same assertion:
  six workspace tabs where five were expected, after the New tab menu was clicked right after
  opening Settings. The workspace ignores that menu only once Settings has rendered
  (`suspended` includes `showSettings`, and the shortcut handler re-subscribes after each
  render). Firing both clicks together reproduced the failure 3 of 3 locally. The test now
  waits for the Settings dialog before clicking the menu (#183); assertions and timeouts are
  unchanged, it passed 3 of 3 locally, and every check on #183's final head passed first time.
- **iPhone paired flow** (`CompanionFlowTests.testPairApproveAndFollowUpThroughTheMac`). The
  pull_request runs of #180 and #183 failed at different steps: a field that held only
  "Pause " after typing (run `38213505465`), and the Forget Mac confirmation not finishing
  after 303 s (run `38216819673`; the same flow takes about 77 s locally). Neither PR changes
  iPhone or Companion code; the push runs passed, and the failed jobs passed on rerun. This is
  the hosted-simulator flakiness already recorded under Known rough edges; no timeout changed.
