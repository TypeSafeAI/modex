## Behavior and boundaries

The Changes pane renders grouped remote patches with compact file headers, old/new gutters, no-final-newline markers, collapsed file bodies, wrap/highlight controls, hierarchical file filtering and keyboard file navigation. A selected line records account/repository/PR/revision/path/side/line; a new head makes that anchor explicitly outdated. Renamed files use the old path for base anchors and the new path for head anchors.

Every read uses `code-review:read` through `Reader`, which verifies `acceptsReply` and cancels superseded requests. The view also checks payload revision, and context path, side and start. Revision sessions use unique request prefixes so cancellation of an old session cannot cancel a new session with a reused ID. Context expands from either end of a fold, adjacent to the relevant change, and can be collapsed again. It comes from the exact requested remote head; the unchanged hunk gaps map its line numbers to the corresponding base numbers. Incomplete patches cannot expand context. No workspace path fallback, Discard callback, patch application, checkout or model invocation enters this view.

`Diff` and `FileIcon` now live in a pure presentation module and remain re-exported by ChangesPanel for compatibility. Local Changes retains its original text renderer and Discard confirmation. Remote line/code/path text is rendered as React text, never HTML. Paths use explicit left-to-right isolation.

## Product bounds and provider bounds

These are product choices, independent of provider limits: up to 1,000 loaded files and ten retained pages, explicit 100-file page actions, an aggregate 8 Mi UTF-16 code-unit text budget per revision (at most 16 MiB of code units, excluding object overhead), four open file bodies, 512 Ki UTF-16 code units per textual patch, 4,000 parsed rows per patch, 40 context lines per action and 200 context lines per open file (including requests reserved in flight). A 3 MiB synthetic text patch is rejected before splitting/parsing. No-text-diff (binary/empty/metadata-only), provider-omitted, oversized and incomplete textual patches have distinct messages and retain provider addition/deletion counts. Loaded files and provider totals are shown separately. Oversized textual payloads are discarded before storing pages, while filenames and provider counts remain. Pages replace earlier reads at the same cursor; repeated cursors or no-progress pages stop pagination with a visible GitHub fallback. Opening another file evicts the oldest open body, keeping mounted patch content bounded.

The host retains at most two revision views in private window memory to preserve loaded pages, selection, filtering, expansion and wrap/highlight state across tab navigation. An account change/sign-out clears them. No PR content or draft is persisted to browser storage. The host's per-PR scroll memory restores scroll position. Expanded context is fetched again after a file body is closed and reopened.

The existing main adapter's GitHub REST API version remains `2022-11-28`. The [current List pull request files documentation](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files), inspected on 2026-10-23, documents a maximum of 3,000 returned files, 30 by default and up to 100 per page. The renderer's 1,000-file display cap is lower and explicitly disclosed with a validated GitHub fallback. The 3 MiB fixture is a stress input, not a claim about GitHub's patch limit. Main's existing context/request/transport bounds remain authoritative.
