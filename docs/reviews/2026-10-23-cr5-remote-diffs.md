## Behavior and boundaries

The Changes pane renders grouped remote patches with compact file headers, old/new gutters, no-final-newline markers, collapsed file bodies, wrap/highlight controls, hierarchical file filtering and keyboard file navigation. A selected line records account/repository/PR/revision/path/side/line; a new head makes that anchor explicitly outdated. Renamed files use the old path for base anchors and the new path for head anchors.

Every read uses `code-review:read` through `Reader`, which verifies `acceptsReply` and cancels superseded requests. The view also checks payload revision, and context path, side and start. Revision sessions use unique request prefixes so cancellation of an old session cannot cancel a new session with a reused ID. Context comes from the exact requested remote head; the unchanged hunk gaps map its line numbers to the corresponding base numbers. Incomplete patches cannot expand context. No workspace path fallback, Discard callback, patch application, checkout or model invocation enters this view.

`Diff` and `FileIcon` now live in a pure presentation module and remain re-exported by ChangesPanel for compatibility. Local Changes retains its original text renderer and Discard confirmation. Remote line/code/path text is rendered as React text, never HTML. Paths use explicit left-to-right isolation.

## Product bounds and provider bounds

These are product choices, independent of provider limits: up to 1,000 loaded files, explicit 100-file page actions, four open file bodies, 512 Ki UTF-16 code units per textual patch, 4,000 parsed rows per patch, 40 context lines per action and 200 context lines per open file (including requests reserved in flight). A 3 MiB synthetic text patch is rejected before splitting/parsing. Binary, provider-omitted, oversized and incomplete textual patches have distinct messages and retain provider addition/deletion counts. Loaded files and provider totals are shown separately. Opening another file evicts the oldest open body, keeping mounted patch content bounded.

The host retains at most two revision views in private window memory to preserve loaded pages, selection, filtering, expansion and wrap/highlight state across tab navigation. An account change/sign-out clears them. No PR content or draft is persisted to browser storage. The host's per-PR scroll memory restores scroll position. Expanded context is fetched again after a file body is closed and reopened.

The existing main adapter's GitHub REST API version remains `2022-11-28`. The [current List pull request files documentation](https://docs.github.com/en/rest/pulls/pulls#list-pull-requests-files), inspected on 2026-10-23, documents a maximum of 3,000 returned files, 30 by default and up to 100 per page. The renderer's 1,000-file display cap is lower and explicitly disclosed with a validated GitHub fallback. The 3 MiB fixture is a stress input, not a claim about GitHub's patch limit. Main's existing context/request/transport bounds remain authoritative.

## Stress observations

Named environment: macOS/Darwin arm64, Apple M5 Max, 128 GiB RAM, Node v24.22.0; Electron/Chromium are the versions pinned by this checkout. The first recorded 1,000-file run loaded ten pages in 3,039 ms including app launch, selected file 1,000 in 59 ms, and had 13,220 DOM descendants in the Changes pane and about 33.1 MB reported JS heap. This is one observed fixture run, not a production latency or memory guarantee. The regression enforces ten file requests, zero unsolicited context requests, four mounted patch bodies, fewer than 25,000 pane DOM nodes, reported JS heap below 256 MiB when available, and selection under 3,000 ms for the named synthetic scenario. A later populated-view run observed 4,229 ms including launch, 57 ms selection, 13,224 DOM nodes and 35.1 MB reported heap. The oversized patch run observed 2,570 ms including launch, 70 pane DOM nodes and 12.7 MB reported heap; no code body mounted. The generated patch was 3 MiB plus eight characters due to whole-line generation. Raw captures, JSON metrics and command logs are preserved outside Playwright's wiped output at `/Users/buns/Documents/ModexEvidence/cr5-remote-diffs-2026-10-23/focused-electron/`.
