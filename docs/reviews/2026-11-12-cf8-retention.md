# CF-8 repeated history and log-memory observations

These controls compare verified pre-CF source `89c98f280292b13fd9b1c7af1bf2fe65cd2fa0d1` with current source `44fb41eecf718cf6648b7c8ee95cab1e85e0e072`. PR #503 changes tests and documentation, so these differences are not attributed to that PR or to a new repair. Both groups use the same installed pinned dependencies and Electron runtime; the baseline is a source export, not a historical shipped binary.

The named host is Apple M5 Max, 18 cores, 128 GiB RAM, arm64, kernel release `27.2.0`, driver Node `v24.22.0`, Electron `44.4.5`. Load averages and exact observation times are retained per replicate in the [public aggregate](2026-11-12-cf8-retention.json). Groups ran sequentially, without randomization, with fixed shapes and varying timestamps. This is descriptive source evidence, not component-causal inference or an ordinary-user latency comparison.

Each source has three fresh-app history replicates: three 200-turn/1,400-item history variants, three warm opens and 63 measured opens per app. Renderer GC is forced only at warm detached endpoints; intermediate renderer and all main observations use natural GC. Each source also has three fresh-app log replicates: one warm-up and 21 measured new-thread streams per app, each with 3 MiB logical output in 48 deltas. The final CLI event repeats aggregated output, so 3 MiB is not a wire-byte total. Every cycle positively checks thread/user identity, completion, opened output and native call counts.

Both log groups measured the same 63 MiB logical output per replicate. Historical sampled window traffic was 1,684,719,770 bytes in every replicate; current traffic was 13,945,579 bytes. Historical maximum main output and opened ASCII output were exactly 3,145,728 bytes: the expected negative control for the current 262,144-byte output limit. Current sampled output never exceeded that limit and its truncation label was verified. The historical-only shallow DOM text-length read verifies full output; that instrumentation difference is another reason not to compare ordinary latency.

Log renderer endpoint deltas were +67,832,596 / +67,830,860 / +67,790,528 bytes historically and +3,437,796 / +3,722,464 / +3,201,784 bytes currently. These runs add 21 legitimate histories and sidebar entries; retained growth is not itself a leak. Uniform all-x payloads also do not represent diverse real logs. The lower current log-memory and IPC observations are consistent with the shipped preview path, but this experiment does not isolate a single implementation change.

History renderer endpoint deltas were -2,324,652 / +662,396 / +668,016 bytes historically and +838,652 / +937,004 / +961,920 bytes currently. Current history endpoints include higher main natural-GC snapshots; no overall memory reduction is claimed. Sampled history-renderer heap ranged from 27,623,008 to 117,432,380 bytes historically and 26,923,300 to 156,610,040 bytes currently. These are sampled observations, not operation high-water values or ceilings. Main natural-GC timing prevents treating its endpoint difference as retained-memory growth.

All 724 historical source blobs, 542 historical build files and 838 current build files stayed unchanged. All six historical cases passed on their first measurement execution, with the expected legacy output-limit violation. Twenty historical archive files were copied and byte-verified. Current-series archives and independent reviews remain separate; all sources and first setup failures are retained. Reported app close calls returned and reported PIDs were absent at audit, without an exhaustive process-tree claim.

These measurements make no arbitrary memory-ceiling, leak-freedom, causal-repair, real-provider/native-platform or human-acceptance claim. The literal S5 assessment below also checks delivered structural caps and child regressions. The one- and five-second sampling points do not prove exhaustive asynchronous settlement. Per-replicate numeric observations, host/runtime versions, timestamps, original-receipt hashes, five-second natural-detach observations and independent-review hashes are in the [public aggregate](2026-11-12-cf8-retention.json). Original logs, full receipts, drivers, manifests, first setup failures and verified recovery archives remain in the private closeout evidence store. Public aggregation omits local executable/app/user-data paths and process IDs without changing numeric observations.

The first historical build was started before source preparation had finished and failed on missing prepared files/dependency links. After that original preparation reached terminal success, the corrected build passed without source, assertion or timeout changes. An initial historical-driver construction used the wrong working directory and failed before app launch; it was corrected before the six-case measurement execution. Pre-execution review also strengthened the unexecuted legacy control to require exact full output. These setup and review corrections are distinct from measurement failures and product defects.

The repeated drivers remain archived diagnostic evidence rather than canonical product tests. The current canonical measurement can be run from an owned checkout after the pinned install and build with `MODEX_MEASURE=/absolute/private/measurement.json pnpm --filter @modex/desktop exec playwright test e2e/transcript-measure.spec.ts --workers=1 --retries=0`. That command records its actual checkout/environment and exercises five fresh-process cold opens plus the streaming/output case; it does not reproduce the separate 63-open/21-stream retention series by itself. Portable repeated-series reproduction remains a follow-up for the separate reproducible capture/performance acceptance criterion; it is not an extra gate in S5.

The existing 500 ms cold-open budget and 256 KiB output limit are unchanged.
