# Code Review packaged-app launch repair

The Code Review shared harness and standalone IPC test ignored `MODEX_PACKAGED_APP` and always launched development Electron with the source app directory. A release run could therefore pass those cases without exercising the selected bundle. Both launchers now use the supplied executable and omit the source directory argument in packaged mode. The shared harness uses the same path when recovering after a crash. Development launches and the synthetic GitHub/isolated-home setup remain unchanged.

The regressions inspect `app.isPackaged` and the running process's resolved executable path. The shared-harness regression repeats these checks after recovery. Before the launcher change, both tests failed with expected packaged `true`, received `false`. Afterward, both passed against the existing local ad-hoc app in 6.7 seconds; both also passed in development mode in 6.2 seconds. The packaged executable was the `release-040-final` worktree's `Modex.app/Contents/MacOS/Modex`, prepared from the older release candidate. This proves executable selection and the exercised read path, not signed-release acceptance or acceptance of current product changes.

The required `pnpm build && pnpm test` sequence passed with exit 0: 2,191 passed, 23 skipped, zero failures or cancellations. Counts by suite were worktree/release 117/117, core 16/16, desktop primary 2,011 passed with 17 skips, desktop second stage 21 passed with six skips, site 10/10, and Store 16/16. Independent read-only review found no blocker, confirmed that reverting either launcher is caught by its packaged regression, and verified that synthetic GitHub isolation is preserved. First-failure traces and logs are retained outside the worktree under `/Users/buns/Documents/Codex/artifacts/modex-land-and-prune/packaged-review-*`. Focused E2E is recorded above; a full local E2E rerun is not claimed, and fresh hosted checks remain required for delivery.

Scope remains Code Review. Standalone desktop-host and Store integration launchers still use development Electron; updater/owner-removal fixture specs deliberately launch fixture entrypoints. Their results must not be described as execution of the selected signed bundle. This repair does not close CR-8, human/reference acceptance, live-write qualification, native updater acceptance, or release publication gates.
