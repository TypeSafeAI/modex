# Retirement safety repair review

This is an uncommitted repair of PR #486 (`b896d44c3e6de0ee0739171f468979f574f32bf9`) integrated into an isolated `retire-safety-repair` worktree from `7cfb29c`. It is not merged, released or exercised against a real retirement target. The original PR owner's worktree was not edited.

## Failures and repair

Four original defects were reproduced against the exact PR module in disposable repositories: a foreign owner could retire another session's work; staged-only blobs disappeared from the bundle; tracked/untracked writes during the second observation could be deleted; and removing the ignored tar did not stop deletion of original ignored data. The external evidence directory is `/Users/buns/Documents/Codex/artifacts/modex-land-and-prune/` (`pr486-review-findings.md`, `pr486-review-repro/`, `pr486-review-repro-races/`).

The repair requires a structurally valid matching owner record and checks that the complete record remains unchanged after external observations. Released records must match the exact current head. An original-index commit is the parent of a separate working-tree commit, so staged-only content remains reachable in the self-contained bundle. Raw working files and unknown ignored files have private tar archives, empty-directory restore verification and byte/mode/link manifests. Nested ignored roots include their parent directories and modes without including sibling data. The complete recovery intent and artifact hashes are persisted before the original checkout moves.

The final observation is not a filesystem lock. The implementation therefore never resets, cleans or deletes original files. Supported `git worktree move` retains the original checkout and Git registration in the private archive run; a no-dereference HEAD update detaches it without touching files or the index. A second snapshot comparison after moving catches changes during that operation. Fresh GitHub and ownership checks precede expected-SHA branch deletion. The original checkout remains indefinitely, including generated data and any writes through file descriptors that raced the observations. Retirement removes the managed path and local branch name but does not reclaim the checkout's disk usage.

## Recovery and interruptions

The durable manifest records `path`, `recoveryPath`, `indexSnapshot`, `workingTreeTar`, `ignoredTar`, hashes and a phase (`prepared`, `moved`, `detached`, `retired`). The existing bundle restore instruction fetches both snapshot commits. In a fresh initialized repository after fetching, set detached HEAD to the manifest tip with `git update-ref --no-deref HEAD <tip>`, then run `restoreIndex` to restore the staged tree and `restoreWorkingTree` to extract raw working bytes into the otherwise empty checkout. The retained registered checkout also preserves the original live index, staged/unstaged distinction and working file permissions.

If moving succeeds but a later step fails, the result is preserved and the manifest identifies the recovery checkout. The branch may remain; a failure after detaching leaves a valid detached recovery checkout. An interruption after branch deletion still leaves the prepared recovery intent, bundle and original registered checkout. Nothing automatically removes or prunes this storage. Tests inject interruption after move, before detach and before branch deletion and prove original index, unstaged bytes, ignored bytes, permissions and registration survive.

## Remaining limits

Owner labels coordinate trusted local sessions; they do not authenticate a caller. The common-Git lock prevents overlapping maintenance operations but cannot stop raw Git commands or external filesystem mutations. Portable archives cover the verified snapshot and exclude regenerable directories; the retained original covers later writes and generated data. Unsupported filesystem node types fail closed. Power-loss behavior was not fault-injected; archives and manifests are flushed, but this is not a claim that arbitrary external writers have flushed their data. Independent follow-up review reported no actionable findings after the nested-parent fix, and the required non-UI repository checks passed. Publication and landing remain pending root direction.
