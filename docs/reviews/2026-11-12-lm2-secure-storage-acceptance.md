All seven implementation steps and six acceptance criteria are supported on signed protected main `5a580d4f98f5b1c62c5801db4400d5b533634082`. The 20 credential/discovery/identity/IPC/export source and test files in the independent audit are byte-identical to their reviewed versions; the intervening #505 runner changes retain the local pinning/no-cloud-fallback guards. This is a narrow consumer check, not a review of the entire credit-conservation feature. The accepted #377 contract dependency is satisfied.

- S1: main persists explicit Ollama, LM Studio and Custom Responses profiles using the accepted connection/model schema and production Settings IPC; scope remains configured same-machine loopback.
- S2: trusted-sender and exact-schema checks, connection ownership/revision, canonical IPv4/IPv6 and repeated DNS/socket checks enforce main-owned endpoints. URL credentials, injection, proxy routing and redirects are refused; no renderer auth helper or shell is executed.
- S3: local tokens use their own opaque namespace in the shared encrypted SecretStore, presence-only replies and fail-closed credential resolution. The packaged native test below proves the real macOS cipher boundary; local-token tests prove namespace, routing and redaction consumers.
- S4: metadata has request/aggregate deadlines, cancellation, response/model bounds and stale-result protection. Exact/manual IDs survive metadata failures when credentials remain readable; unavailable credentials or rejected IPC cannot reconstruct descriptors. Runtime-exposed installed/loaded state stays separate from unknown.
- S5: generative, embedding and other advertised model kinds remain distinct; advertised tools do not qualify coding. Known cloud-routed models are excluded and unknown downstream inference locality remains unverified.
- S6: Settings and refresh use only fixed metadata routes, with no inference, install/download, model load/unload, directory scan or port enumeration. The cold-load explanation is separately delivered by #498.
- S7: revisions, tombstones, exact credential binding, active-run edit/delete refusal and retained snapshots prevent replacement/deletion from redirecting an existing run while preserving readable history.
- AC1: normal, empty, malformed, unavailable, authenticated and delayed fixtures pass through production main/IPC; recorded requests carry only bounded metadata, never project content or inference.
- AC2: endpoint, DNS/redirect/proxy and forged-IPC tests enforce the same production boundary.
- AC3: safe renderer descriptors omit tokens; URLs reject credentials; fixed diagnostics and reflection guards avoid secret echoes; pre-event/log/record/snapshot redaction covers split and truncation boundaries. The actual saved and reopened Task Note export retains positive marks while omitting tokens. Authenticated discovery sends exactly its own connection token; tokenless requests have no Authorization header, and a seeded cloud credential is never forwarded. The native proof composes with these separate consumer tests; the generic key test alone does not establish every surface.
- AC4: identity includes connection and revision; delayed edit/switch/delete responses cannot become current. #503's canonical endpoint-replacement case preserves the old thread target.
- AC5: explicit custom/manual identities remain available for compatibility testing; embedding/nontext/cloud exclusions cannot become coding agents. The downstream compatibility-test interface and execution admission belong to their own issues.
- AC6: exact request fixtures prove discovery makes no forbidden calls, and revision/history/active-run guards prevent silent rebinding.
