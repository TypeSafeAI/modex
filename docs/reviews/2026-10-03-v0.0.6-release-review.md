# Desktop v0.0.6 release review

The first candidate was `main` at `fc8c699` plus release PR #97. Its signed tag targeted
`181ce4d`, but the release run was cancelled before environment approval. No v0.0.6 assets
were published. The replacement candidate adds the work merged since that tag and the
Jev-inspired palette. The previous release is v0.0.5 (`e2c2fbc`). The planned distribution is macOS Apple Silicon, Developer ID
signed for Soul Protocol LLC (`9LR8Z8UQ9X`), notarized and stapled. The monorepo and core package
keep their existing versions.

## Scope

| Area | Change |
| --- | --- |
| UI and privacy | #80 centers content after hiding the sidebar. #89 refines the dark surfaces, type hierarchy and composer; fixes the follow-up placeholder overlap and makes offline screenshot capture deterministic. The replacement candidate uses near-black blue surfaces, Jev's dark pink for focus and TypeSafe UI's warmer pink for primary actions. #100 adds Streamer Mode to redact sensitive transcript content. |
| Input and project safety | #93 restores an unsent message after a failed send or thread creation without overwriting newer typing. #94 clears drafts and thread view state when a project is removed, leaving files on disk. |
| Changes and test reliability | #82 handles discard in an unborn repository. #85 surfaces Git diff failures and handles rename destinations beginning with `-`. #102 scopes Changes status, diff, and revert to the selected project when it is a subdirectory of a repository. #84 drains the EPIPE test fixture before blocking the event loop; #98 waits for the terminal supervisor to stop before testing close. |
| Account readiness | #96 separates CLI installation/version, structured sign-in status and unverified model access. Status checks run no coding turn; missing, older and failed CLI checks do not claim readiness. |
| Provider research | #95 records conditional Gemini and Grok CLI/ACP feasibility decisions. Neither backend is enabled. |
| Sign-in and recovery | #91 adds CLI-owned Claude login. #92 adds scoped ChatGPT authorization and account-isolated Codex processes while coding turns stay in the CLI. #104 adds persisted failure cards and Retry, replacing draft #68. |
| Browser review | #105 adds a localhost development bridge for exercising the real renderer in Chromium, excluded from packaged builds. |
| iPhone companion | #103 adds the opt-in paired HTTPS service and QR pairing screen. The native SwiftUI companion supports local-network threads, follow-ups and one-time approvals. Request revocation and stale-response protection are tested; coding turns remain CLI-owned on the Mac. |

Approval rules remain off; their Settings UI and receipts are being reviewed separately.
The iPhone TestFlight release and physical-device acceptance have separate gates. The Mac
companion service is included here so the iPhone app can pair with a released Mac build.

## Verification

- On the rebased release branch, `npm run build && npm test && npm run typecheck` passed:
  15 core and 192 desktop unit tests. `npm run test:e2e` passed all 85 Electron tests,
  including Streamer Mode, scoped Changes, composer recovery, account status, project
  removal and PTY lifecycle.
- An ad-hoc `npm run dist -w @modex/desktop` produced a 0.0.6 arm64 bundle, DMG and ZIP
  from the rebased branch. The bundle icon matches `build/icon.icns`; `hdiutil verify` and
  `unzip -tq` passed. All 85 Electron tests passed with `MODEX_PACKAGED_APP` pointed at
  the 0.0.6 bundle. The ad-hoc artifact is not for publication.
- The local release script built and notarized the 0.0.6 app and DMG with Soul Protocol LLC's
  Developer ID identity. Its independent `--verify` pass confirmed strict nested signatures,
  hardened runtime with library validation, Gatekeeper acceptance for app and DMG, stapled
  tickets on both and on the app inside the ZIP, container integrity, arm64 version, and icon.
  The signed packaged app passed all 85 Electron e2e tests. The e2e launch helper now polls
  native window visibility: repeated signed launches exposed a missed one-time `show` event
  after DOMContentLoaded, which had stalled the initial packaged run.
- The first candidate's release PR passed both macOS CI runs. Its signed tag was pushed, but
  Release run 37185413131 was cancelled while waiting for `release-signing` approval. No
  GitHub release was created.
- The replacement candidate built and typechecked. All 15 core unit tests, 231 desktop
  unit tests and the Chromium bridge test passed; 90 Electron e2e tests passed, including
  the palette's token and contrast checks. On this busy local machine, two default-parallel
  unit runs each had one terminal-process fixture timing failure; the full desktop unit suite
  passed when Node ran test files serially, and the terminal suite passed alone. Exact-head
  macOS CI remains the required parallel-run check.
- Both macOS CI runs passed on palette PR #106's initial head. The local sign-only build exposed
  a duplicate `mac.notarize` CLI flag and a certificate expiry comparison done as text; these
  now pass one flag and compare parsed dates. The rebuilt app and DMG passed Developer ID,
  hardened-runtime, nested-code, container, arm64, version and icon checks with the 2031 leaf
  certificate (`EE732DF3…DAF3E7F`). The first packaged e2e run stalled when Settings asked
  macOS protected storage for ChatGPT status in `MODEX_E2E`; the source app and both signed and
  unsigned packages isolated that path. Giving the e2e ChatGPT home the existing test cipher
  fixed it. All 90 packaged Electron e2e tests then passed on the rebuilt signed bundle.
  This sign-only package is not notarized or publishable.
- Replacement candidate: local notarization and stapling, CI on the updated PR head,
  a replacement signed tag, protected `Release` workflow, downloaded-asset verification and
  publication remain to be recorded below. The first candidate's local notarization evidence
  does not establish the replacement build.

### Companion integration

- Companion PR #103 merged as `053b140` after both desktop and iPhone jobs passed in
  CI runs `37199734424` and `37199737074`. Native verification includes 10 unit tests and
  pairing, single approval, follow-up, cancelled forget, and confirmed disconnect in the
  simulator. The signed iPhone 0.1.0 (2) distribution IPA passed strict signature and ZIP
  checks; Apple upload, internal tester access, and physical-device acceptance remain open.
- The combined palette and companion candidate passed build, typecheck, 15 core tests,
  239 desktop tests plus the browser bridge test, and all 91 source e2e checks. Its sign-only
  app and DMG passed signature, hardened-runtime, library-validation, container, icon and
  arm64/version checks using leaf `EE732DF3…DAF3E7F`. All 91 e2e checks then passed with
  `MODEX_PACKAGED_APP` set to that signed app (the browser development check still runs
  against the separate development bridge). This build is not notarized or publishable.
- The lockfile also updates the dev-only `http-cache-semantics` dependency from 4.2.0 to
  4.3.0 within Electron builder's existing compatible range. It is absent from the packaged
  app; this follow-up does not change its runtime payload. The refreshed lockfile audit
  reports zero vulnerabilities. A clean install, build, full unit suite and typecheck passed
  again with 4.3.0 installed.
- The paired iPhone flow also passed with `MODEX_IOS_LAN=1`, binding the Mac's actual private
  network address instead of loopback. This exercises the same address-selection and TLS
  path used by the app, while remaining simulator evidence rather than physical-iPhone
  acceptance.

## Proof limits

A live Haiku turn through Modex's `ClaudeBackend` and Claude Code 2.1.288 completed on
2026-10-04 using the signed-in Claude subscription. It returned the requested acceptance
marker with tools disabled and zero tool requests. This covers that account/model pair;
it does not establish access to every model or live Claude tool execution.

Offline fixtures do not establish subscription eligibility or the conditional Gemini/Grok
backend contracts. Human VoiceOver acceptance and installation
on a fresh Mac remain untested. Windows and Linux installers and auto-update are not in this
release.
