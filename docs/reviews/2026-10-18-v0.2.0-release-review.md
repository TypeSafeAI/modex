## Candidate behavior and compatibility

- **Routines run only while Modex runs.** A routine runs a read-only Chat or Plan turn in one
  project. Every approval it asks for is refused, with a receipt. Missed runs run once on wake, and
  an interrupted run is never repeated. Nothing schedules turns while Modex is quit.
- **Jev decisions leave receipts.** Auto routing, follow-ups and approval rules ask Jev through one
  service. Each judgment is recorded in `app/decisions.jsonl` with Jev's typed answer or the error,
  never the request. Without a Jev key, behavior is unchanged.
- **The event journal stays opt-in** (`MODEX_EVENT_JOURNAL=1`). Without it, desktops and the phone
  reload as before.
- **Notes.** No migration. A stuck rename left by an earlier version (a folder with `\` in its name)
  is set aside on first launch, and its folders stay as they are.
- **Updates.** v0.1.0 → v0.2.0 is the second published-to-published upgrade. The first, v0.0.12 →
  v0.1.0, was recorded on the release Mac on 2026-10-18 (see the v0.1.0 review).
- **Platforms.** macOS arm64 is Developer ID signed (Soul Protocol LLC) and notarized by the Release
  workflow. Windows and Linux candidates are built and checked the same way as v0.1.0's. Whether
  they are published is decided at publication.

## Release gates

1. Land this preparation through the guard, then sign tag `v0.2.0` on its squash (Val's go-ahead).
2. The Release workflow, after `release-signing` approval:
   - signs, notarizes and staples the app and DMG, then runs the packaged E2E;
   - runs the three hosted native updater scenarios and the Windows and Linux checks;
   - attaches the candidates to a draft.
3. Download the draft's assets and verify them independently:
   - `shasum -c`, the codesign leaf, `spctl` for the app and the DMG, and `stapler`;
   - the packaged E2E against the downloaded app.
4. Publish, then check `releases/latest` with the updater parser shipped in v0.1.0.
5. Upgrade the release Mac's v0.1.0 through its own banner with an unsent draft open. Record the
   `app/update-recovery.json` attempt, the sha512 against the published ZIP, the relaunch, About and
   the draft.
