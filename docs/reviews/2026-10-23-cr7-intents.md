## Observable behavior

| Scenario | Observed/model requirement | Scope |
| --- | --- | --- |
| Draft race | Late version-1 response cannot replace version-2 edit | Durable local CAS, not renderer integration |
| Same PR number in different accounts/repositories/revisions | Draft lookup stays isolated | Sign-out UI remains a future gate |
| Two rapid clicks | Exactly one permit and one counted mock request | No provider transport |
| Process killed after admission, before mock request | Zero requests; restart stays unknown and grants no replacement | Conservative uncertainty window |
| Process killed after mock request | One request; restart stays unknown and grants no replacement | No automatic replay |
| Storage failure before rename | Zero permits; current instance fenced; unused preview rejected at restart | Original failure preserved |
| Storage failure after rename/directory sync | No permit; restart sees unknown | Does not infer an unsent operation |
| Wrong identity, changed repository/head/base/target/session or permission | No dispatch permit | Future source of trusted context remains unwired |
| Forged/reused confirmation | No dispatch permit | Process-local object identity, not a server idempotency key |
| Stale preview cancellation | Can reject prepared once, then explicitly prepare at the new head | Dispatched/unknown cannot be cancelled |
| Ambiguous or absent readback | Remains unknown and blocks another intent | Even an empty read is insufficient |
| Same-body repeated operation | Earlier digest/remote receipt cannot confirm a distinct attempt | Exact correlation remains an adapter obligation |
| Malformed persisted state/digest/duplicates/extra fields | Startup refuses and preserves original bytes | Does not reset damaged receipts to an empty store |

Confirmed and rejected results retain drafts, including newer edits. Intent payloads and public results are copied, so caller mutation cannot change the stored operation. Receipt storage is bounded and never evicts duplicate protection to make space. Single-main-process ownership is required; stale sequential owners fail their compare-and-replace proof, but this is not an interprocess lock or remote exactly-once guarantee. No automatic credential collection, raw transport errors or provider output are stored. User-authored draft text is local private data and is not automatically redacted.
