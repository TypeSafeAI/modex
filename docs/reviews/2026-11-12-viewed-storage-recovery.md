# Viewed storage recovery

This repairs the [reproduced #506 follow-up](https://github.com/TypeSafeAI/modex/pull/506#discussion_r4548813336) on base `e6e644ea25cd5f428b8699e0b1e9cfbaa022e49d`: when localStorage rejects writes, marking B erased the earlier session mark A, and a later toggle could resurrect a file just unmarked from persisted data. The original source always reconstructed the next state from stale storage. Existing C65 Viewed behavior is local, account/repository/PR/revision-bound and performs no GitHub mutation.

A WeakMap now retains only failed writes per storage object. Later toggles and helper reads use the pending document; the next successful write persists accumulated changes and removes the fallback. Normal successful storage reads continue observing external updates. A fresh storage object or renderer restart has no access to unpersisted marks. Cross-window convergence while storage fails is not promised; the current renderer's pending document is authoritative until a local write succeeds. Existing 200-PR and 3000-path limits remain.
