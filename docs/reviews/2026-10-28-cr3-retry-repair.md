# CR-3 retry ordering repair

PR #437 at `8b481e046a2b199c8b5ec5c6424660f3bdf4bb5f` introduced an asynchronous gap between the first attempt finishing and its sign-in retry starting. A newer read or cancellation in that gap could be overwritten by the older retry. Deterministic regressions reproduced all three cases: a newer read, cancellation of the slot, and cancellation of all slots.

The reader now checks the live attempt and begins its sole permitted retry within the same continuation. A newer read or cancellation therefore supersedes the currently registered attempt; an old retry cannot reclaim the slot after either operation. Account and reply-scope validation, fresh request IDs, and the one-retry limit remain in place.

The three new tests failed before the repair. They and the existing focused reader retry/cancellation cases passed after it. Full root build and unit validation passed: 2,214 passed, 23 skipped, zero failures or cancellations. All 23 focused Code Review navigation, regression and populated-scroll E2E cases passed in 1.7 minutes. Independent review found no blocking findings. The full repository E2E run passed: 473 desktop cases, seven skipped, and seven site cases. The cold transcript median was 127.2 ms against the unchanged 500 ms gate. The Store browser-tools recovery case, including shutdown, passed locally; this does not explain the separate hosted shutdown timeout on #433. These tests exercise the production Reader with a controlled main-process transport; they do not constitute live GitHub sign-in or human accessibility acceptance.
