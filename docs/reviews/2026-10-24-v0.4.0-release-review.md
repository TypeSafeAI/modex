# v0.4.0 release review

Desktop v0.4.0 ships task context and answering from anywhere:
- a saved task note reopens as the task it saved;
- a turn lists the files it touched and says whether a check verified its last change;
- Claude's task tools and Codex's proposed plans become the turn's plan;
- Codex's Plan mode runs in Codex's own plan mode;
- an agent's questions can be answered from the iPhone, and stay correct across replay and reconnect;
- keyboard focus, Jump to latest and Codex Stop behave as a person expects.

It also carries the Code Review workspace, hidden in built apps, and main-only local-model
discovery, which has no UI. Val asked for the next version on 2026-10-24. iPhone Companion 0.4.0
(9) is cut from the same tag.

This preparation starts from protected `main` at `e17aebd2fd4a2c691ee4e8946b5c2ef767aa023a` (#403).
It changes only the desktop and Companion versions and the release records.

## Candidate behavior and compatibility

- **Updates.** v0.4.0 is the first release that v0.3.0's background update reaches. A v0.3.0
  check downloads and verifies v0.4.0 without a click, and it installs on **Restart to update** or
  the next time Modex quits. v0.2.0 and older still need one **Download update** click. Windows and
  Linux still install by hand. [Download and restart](../update-recovery.md#download-and-restart).
- **Transcripts and notes.** Old transcripts and notes read unchanged. Notes saved before CF-7's
  task view have no task view, and earlier turns have no files-touched or verification line. Nothing
  is backfilled or inferred.
- **The event journal stays opt-in** (`MODEX_EVENT_JOURNAL=1`). Questions and a plan saved by v0.3.0
  load closed and readable on every client (`conversation-migration.test.ts`).
- **iPhone.**
  - Companion 0.4.0 (9) answers an agent's question card through the Mac's broker. A secret goes in a
    secure field that is held only in memory.
  - It closes cards that were answered, withdrawn or stopped while it was away.
  - Older Companion builds keep receiving a question as text to answer on the Mac.
  - Build 9 supersedes 0.3.0 (8), which was never uploaded.
- **Codex Plan mode** uses Codex's plan collaboration mode with the picked model and effort, and stays
  read-only. A Codex that refuses the mode falls back to the old prompt, with a notice.
- **Code Review is hidden.** Built apps show the destination only when the local switch
  `modex.codeReview` is `on`; development builds show it. Gate A (#319) is not accepted, so this
  release does not offer Code Review.
- **Local models.** Main keeps loopback-only connection profiles and reads bounded model metadata
  through a local-only IPC channel, under the metadata exception that AGENTS.md records as Val's
  approval. There is no UI, no execution and no inference, so nothing in the app reaches it yet.
- **Platforms.** macOS arm64 is Developer ID signed (Soul Protocol LLC) and notarized by the Release
  workflow. Windows and Linux candidates are built and checked as for v0.3.0. Whether they are
  published is decided at publication.

## Release gates

1. Land this preparation through the merge queue.
2. Sign tag `v0.4.0` on its squash with a key in the Release workflow's `TAG_ALLOWED_SIGNERS`.
   Every release tag from v0.0.9 to v0.3.0 was signed with `SHA256:Apqee2EOZLXmfVUUy/QX1QLBn9g10SuzHbK5ARks19E`.
   Push only the tag.
3. The Release workflow, after `release-signing` approval:
   - signs, notarizes and staples the app and DMG, then runs the packaged E2E;
   - runs the three hosted native updater scenarios and the Windows and Linux checks;
   - attaches the candidates to a draft.
4. Download the draft's assets and verify them independently:
   - `shasum -c`, the codesign leaf, `spctl` for the app and the DMG, and `stapler`;
   - the packaged E2E against the downloaded app.
5. Publish, then advance `apps/site/release.json` and record the publication, as #339 did for v0.3.0.
6. On the release Mac, let v0.3.0 download v0.4.0 in the background with an unsent draft open, then
   quit. Record the `app/update-recovery.json` attempt, the sha512 against the published ZIP, About
   and the draft.
7. iPhone Companion 0.4.0 (9) from the same tag. Val is needed at the Mac for 1Password:
   - `op run --env-file=.env.release -- apps/ios/ModexCompanion/Scripts/release-testflight.sh`;
   - What to Test, the External group and beta review.
