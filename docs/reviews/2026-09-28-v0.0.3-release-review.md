# Desktop v0.0.3 release review

The release scope is reviewed main after [PR #32](https://github.com/TypeSafeAI/modex/pull/32) (the embedded terminal panel) plus the changes below. Desktop v0.0.2 was the previous release. The distribution remains macOS Apple Silicon, ad-hoc signed and not notarized. The monorepo and core package keep their existing versions.

This review extends the [v0.0.2 release review](2026-09-28-release-review.md) and the [embedded terminal review](2026-09-28-terminal-review.md). The terminal panel ships in this release; its lifecycle contract is unchanged.

## What changed

| Area | Change and regression evidence |
| --- | --- |
| Unsent text | Composer text is owned by the app, keyed by thread (or by draft revision for a new chat), instead of by the composer instance. Switching threads keeps each thread's unsent text; the sidebar marks such threads with a pen glyph until they are sent; sending, deleting the thread, or ⌘N clears it. An Electron scenario switches between two threads and a draft, checks the marker, sends, and checks both the text and the marker are gone. The v0.0.2 isolation scenarios (project switch shows an empty composer; ⌘N always starts empty) still pass unchanged. |
| Terminal panel polish | The panel enters with a 180 ms fade and 6 px rise (0 ms under Reduce Motion). The resize affordance is a 2 px edge that lights up on hover, focus and drag instead of a 6 px accent bar. An exited shell shows its code in a warning chip. The "Loading terminal…" placeholder takes the panel's default height, so the first open no longer jumps from 140 px to 240 px when xterm arrives. |
| Test windows and the keyboard | Under `MODEX_E2E` the window is shown inactive. Playwright drives it over CDP and never needs it active; an active test window swallows whatever the developer types elsewhere, and a real shell in the terminal panel then runs those keystrokes. A local run on a machine in use reproduced this as garbled terminal input and closed sessions in 7 of 56 scenarios; the same scenarios passed on rerun with the inactive window. This also explains the unexplained first-run failures noted in the terminal review. |

The parked follow-up-suggestion work from the `chat-workspace` branch is not part of this release: it adds a routing question and an IPC surface, which is outside a patch scope. PRs #30 and #31 (Copilot CI stabilisation attempts) predate #32 and would remove the terminal panel; they are superseded.

## Verification

Checked on macOS 26.6.2, Apple Silicon, Node 24:

- Build and TypeScript checks passed.
- 120 unit tests passed: 15 core and 105 desktop.
- 57 Electron end-to-end tests passed from source and against the packaged application, using isolated homes and temporary repositories. The suite adds the unsent-text scenario to the v0.0.2 set and the six terminal scenarios and four terminal lifecycle scenarios from the terminal review.
- The app reports version 0.0.3 and arm64 architecture. `codesign --verify --deep --strict` passed with an ad-hoc signature; DMG and ZIP integrity checks passed.

Run the source checks from a worktree:

```sh
npm run build
npm test
npm run typecheck
npm run test:e2e
```

Build and exercise the actual bundle:

```sh
npm run dist -w @modex/desktop
MODEX_PACKAGED_APP="$PWD/apps/desktop/release/mac-arm64/Modex.app/Contents/MacOS/Modex" npm run test:e2e
codesign --verify --deep --strict --verbose=2 apps/desktop/release/mac-arm64/Modex.app
hdiutil verify apps/desktop/release/Modex-0.0.3-arm64.dmg
unzip -tq apps/desktop/release/Modex-0.0.3-arm64.zip
```

## Proof limits

Offline scripted CLI tests do not establish live-provider execution, paid-model behavior, or human VoiceOver acceptance. Unsent text is renderer state: it survives switching threads, not quitting the app. This release does not add notarization, a custom app icon, auto-update, or Windows/Linux installers.
