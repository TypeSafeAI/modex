# CR-7: bind the intent model to CR-5's anchors and CR-4's slots

#326. Base: `main` at `a10fcc4`. Branch `cr7-anchors`.

## Why

CR-5 (#395) and CR-4 (#393) landed after the unwired draft/intent model (#399, integrated by #404).
The goal for #326 asks for a check that their anchors and callback slots match the model.

- **CR-5 anchors didn't match.** `anchorFor` returns a `LineAnchor` with seven fields. The seventh,
  `commitSha`, is the commit its line numbers count in: the head, or the proven diff base for the
  base side. The model's `ReviewAnchor` had six fields, and its exact-shape check refused the real
  anchor. The digest also didn't bind the diff base.
- **CR-4 slots match.** `OverviewActions` (`comment`, `edit`, `requestReviewers`) are zero-argument
  callbacks, so the host binds the scope it rendered. `comment` maps to a `comment` draft. `edit` and
  `requestReviewers` wait for decisions 3 and 4. Submit-review, the state menu and Merge have no
  slot yet; the write increments add them.

## Change

- `LineAnchor` moves into the shared contract (`src/shared/code-review.ts`). `patch.ts` re-exports
  it, and the model's `ReviewAnchor` is that type, so a later change to either side breaks the build.
- The model accepts exactly the seven-field shape. `commitSha` must be 40-hex and, on the head side,
  the revision's head. It is in the intent digest.
- Not proved here: that a base-side `commitSha` is the merge base, or that a line is in the provider's
  patch. The future write adapter checks both against the fresh read (`PrFiles.diffBaseSha` and the
  file's patch) before dispatch.

No GitHub mutation, IPC channel, UI control or capability is added. Write authorization and scope
decisions 2–4 are still unanswered; the questions are on
[#326](https://github.com/TypeSafeAI/modex/issues/326#issuecomment-6390523576).
