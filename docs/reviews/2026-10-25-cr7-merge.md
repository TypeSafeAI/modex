# CR-7: Merge through the gh login

#326, second increment. Base: `main` at `a10fcc4`. Stacked on #413 (`cr7-write-submit`), and it carries
#412's preflight commit. Branch `cr7-merge`.

## Change

- **Contract:** `merge-check` and `prepare-merge` ops; `MergeCheck`; fixed texts for each reason Merge
  isn't offered (`MERGE_BLOCKS`). `prepare` refuses a merge operation.
- **Transport:** one PUT, `repos/{o}/{r}/pulls/{n}/merge`, with a body. One more GET shape, the target
  branch's rules. No path segment may be `.`, `..` or their encodings.
- **Service:**
  - It reads the facts fresh for every check, preview and submit: push permission, the repository's
    allowed methods, GitHub's `mergeable` and `mergeable_state`, and whether the target's rulesets
    require a merge queue.
  - #412's `mergePreflight` decides; only an offered method can be previewed or sent.
  - The PUT carries `sha` = the reviewed head from the durable intent.
  - A read-back confirms a merge only if the PR merged, by this account, at that head.
- **UI:**
  - The header's Merge opens a panel, disabled until the PR has loaded and main has answered.
  - The panel shows method radios for the allowed methods only, or the reason with Open on GitHub.
  - Then a preview that names the account, destination and head, and a confirm button.
  - After a merge, the PR is read again.
- `capabilities()`: `merge` follows the connection; each PR is main's answer.
- The preflight is unchanged except that `MergeMethod` and the unavailable reasons now come from the
  shared contract.

## Validation

Everything below is mock or synthetic `gh`. **No live merge was run**, and no real PR was merged.

- **Unit** (`test/code-review-writes.test.ts`, 7 new tests):
  - exact requests and the PUT allowlist;
  - only allowed methods are offered;
  - a check and a preview send nothing;
  - two concurrent submits merge once, with `sha` = head;
  - each blocked, unknown or unreadable state is unavailable, and so is missing or unreadable push
    permission;
  - a moved head, a moved target, a withdrawn method, newly blocked state, lost push or another account
    between preview and merge each send nothing and spend the preview;
  - 405 and 409 are refused;
  - a 502 after GitHub merged → unknown → reconcile confirmed;
  - merged by someone else stays unknown and blocks the PR;
  - a crash after admission restarts unknown, and nothing merges again.
- **IPC** (`test/code-review-write-ipc.test.ts`):
  - a merge through the compiled main handler, the real gh transport and the synthetic gh, with exactly
    one PUT;
  - the static check now pins exactly one `PUT`, to the merge endpoint, carrying the intent's head.
- **Electron** (`e2e/code-review-actions.spec.ts`, 4 new tests):
  - two methods are offered, not the disallowed one; the preview names `ada-fixture` on
    `example-org/lending #73` at `cccccccc`; a double click merges once, and the header turns *Merged*;
  - blocked rules show the reason and Open on GitHub, and lost push permission is refused;
  - a head move between preview and merge sends nothing;
  - SIGKILL during a merge GitHub recorded → restart in doubt → *Check GitHub* confirms it, with one PUT.
- Existing specs updated where Merge used to be inert:
  - navigation: under `MODEX_E2E` it now says writes are disabled;
  - regressions: Merge was removed from the list of controls that send nothing.
- Found and fixed: before the PR loaded, the fallback Merge button was enabled and did nothing. It now says
  it's waiting for the PR.
- **Full run** (`pnpm build && pnpm test && pnpm test:e2e`): exit 0.
  - Desktop unit: 1,969 passed, 17 skipped. Other unit suites: 180 passed, 5 skipped.
  - Desktop E2E: 460 passed, 7 skipped (17.8 min). Site E2E: 7 passed.
