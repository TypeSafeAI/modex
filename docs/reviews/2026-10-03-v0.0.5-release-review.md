# Desktop v0.0.5 release review

The release scope is `main` after [PR #51](https://github.com/TypeSafeAI/modex/pull/51) (Jev
settings, routing limits and settings save transactions, which closes #40–#50 and carries the
four P1 constraints), plus the release PR, [#69](https://github.com/TypeSafeAI/modex/pull/69).
Desktop v0.0.4 was the previous release. The
distribution is still macOS Apple Silicon only. It is the first release that is **Developer ID
signed (Soul Protocol LLC, `9LR8Z8UQ9X`), notarized and stapled**, and the first whose
artifacts come from the protected `Release` workflow rather than a maintainer's Mac. The
monorepo and core package keep their existing versions.

This review extends the [v0.0.4 release review](2026-09-29-v0.0.4-release-review.md). It
concentrates on what changed in the release path itself, because that path ran end to end for
the first time and three of its defects were only visible there.

## What changed

| Area | Change and regression evidence |
| --- | --- |
| Signing and notarization | #38, #52, #53: hardened runtime with library validation kept on, a hash-pinned `mac.sign` hook for the two same-name certificates, `scripts/release-mac.sh` and the `Release` workflow. This PR adds DMG signing, notarization and stapling, which electron-builder never did, and the CI keychain import (see Findings). |
| Release environment | `release-signing` now exists. BunsDev is the required reviewer, admins cannot bypass, and only `v*` tags may deploy. All seven secrets are set. The `.p12` holds exactly one identity (`EE732DF3…DAF3E7F`, valid to 2031), its key, and the G2 intermediate. That was checked before upload: two subjects, one private key, and the key's public half matches the leaf's. |
| App icon | `docs/branding/modex-icon.png` (#39) placed on the macOS icon grid (824 px rounded body on a transparent 1024 px canvas, soft shadow, faint edge) by `apps/desktop/scripts/make-icon.swift`, packed into `apps/desktop/build/icon.icns` by `iconutil`. The verify step compares the bundle's `CFBundleIconFile` byte for byte with that file, so a build that falls back to Electron's icon fails. |
| Terminals | #65 pins `node-pty@1.2.0-beta.15`, which closes the placeholder `/dev/ptmx` and `kqueue` that 1.1.0 leaked per spawn. #64 makes a dead supervisor always report a missing cleanup receipt. A new packaged-capable e2e, *closing terminals releases every PTY the app opened*, opens and closes five terminals in the running app and counts its main process's `/dev/ptmx` handles with `lsof`. It also asserts that an open terminal is counted, so it cannot pass vacuously. |
| Jev settings and routing (P1) | #51: CLI-only transport is honoured, saved judge configuration refreshes, existing CLI sessions are preserved, and routing stops before execution when effort or premium limits cannot be guaranteed. Settings separates drafts from immediate key and reset actions, keeps a failed save for retry, and has four accessible sections with persistent Save and Cancel. Its own review evidence is linked from the PR. |
| Contributor fixes | #61: a send that cannot start returns `{ ok: false, error }` and shows the error toast. #60: renamed files diff as renames in Changes. #62: `worktree.sh` works offline. |
| Approval rules, part 1 | #54: plumbing only, with the gate off and no UI. Nothing user-visible. |

## Findings

| # | Severity | Finding | Resolution |
| --- | --- | --- | --- |
| 1 | High | The DMG was never notarized or stapled. electron-builder notarizes only the `.app`, and `dmg.sign` would pick the first certificate by name (the short-lived one) without a timestamp. The first full local run stopped at `stapler validate` on the DMG, exit 65, as designed. | `release-mac.sh` signs the DMG by hash with `--timestamp`, submits it to `notarytool --wait`, refuses anything but `Accepted`, and staples. Verify now checks the DMG's leaf certificate and its Gatekeeper verdict (`spctl -t open --context context:primary-signature`). |
| 2 | High | The CI path could not have signed the DMG. electron-builder's `CSC_LINK` import deletes its keychain when it exits. | The workflow imports the `.p12` into its own temporary keychain, puts it on the search list, and exports `CSC_KEYCHAIN`. The script then resolves and signs by hash exactly as on a Mac. The keychain is deleted in an `always()` step. |
| 3 | High | Tag verification could never pass in CI. `actions/checkout` leaves the pushed tag as a lightweight ref, so `git tag -v` failed with *cannot verify a non-tag object of type commit* (rehearsal `v0.0.5-rc.1`). | The step fetches the annotated tag object and refuses anything that is not an annotated tag before `git tag -v`. |
| 4 | High | A fresh checkout could not build the release. `@modex/core` has no `dist/` until the root build runs, so the desktop `tsc` failed with *Cannot find module '@modex/core'* (rehearsal `v0.0.5-rc.2`). Local worktrees only passed because the root build had already run there. | `release-mac.sh` builds `@modex/core` first. The bundle ships core's `dist/`, which was confirmed in `app.asar`. |
| 5 | Low | The pre-rebase packaged e2e rehearsal failed one test (*drafts: a new chat is nothing until its first send…*, a 30 s click hang). The machine's load average was about 216, and the suite took 14.7 min. | The same test passed 3/3 alone against the same bundle, and all 76 passed in the final packaged run. It was load, not the build. Nothing was waived: the packaged e2e on CI gates the upload. |
| 6 | Low | `node-pty` is a pre-release. | Kept, because 1.1.0 leaks a PTY per terminal. The beta passed the unit suite, the packaged e2e (including the PTY count), and library validation in the hardened runtime. `docs/status.md` says to move to 1.2.0 stable when it ships. |
| 7 | Low | A unit test from #64 failed once on this PR's CI (push run [37141344169](https://github.com/TypeSafeAI/modex/actions/runs/37141344169), head `9ca9c1b`, a docs-only change over a head that had passed twice). *supervisor death seen as a failed CLOSE write still reports a missing cleanup receipt* reported *the supervisor survived SIGKILL*: the killed supervisor was neither a zombie nor reaped after the full poll, which ran 16 s on a slow runner. The test blocks the event loop on purpose (`Atomics.wait`) so `close()` meets EPIPE, so nothing drains the PTY master while that runs. A likely cause is a dying process that waits in exit for its tty output to drain. The product never blocks its loop that way. | Rerun, not waived, and recorded under *Known rough edges* in `docs/status.md` with the hypothesis to test. |

## Verification

These results are for the release branch rebased on `main` at `d9414b5` (#51). Locally the
machine was macOS 26.6.2 on Apple Silicon with Node 24. CI used GitHub's `macos-latest`
runner with Node 22.

- Build and TypeScript checks passed. 195 unit tests passed: 15 core and 180 desktop.
- 76 Electron end-to-end tests passed from source on CI
  ([run 37140744440](https://github.com/TypeSafeAI/modex/actions/runs/37140744440)).
- `scripts/release-mac.sh` ran in full locally:
  - It signed with `EE732DF3F48D7535561AF54D3FFFC4B44DAF3E7F`, team `9LR8Z8UQ9X`, hardened
    runtime, `allow-jit`, and no `disable-library-validation`. node-pty's `pty.node`,
    `spawn-helper` and the terminal supervisor carry the same team.
  - Apple accepted the app and the DMG. For both, Gatekeeper reported
    `accepted, source=Notarized Developer ID`.
  - Stapler validated the app, the DMG, and the app inside the ZIP. `hdiutil verify` and
    `unzip -tq` passed.
  - The bundle reports 0.0.5 and arm64. `icon.icns` matches `build/icon.icns` byte for byte.
- 76 Electron end-to-end tests passed against that signed, notarized bundle
  (`MODEX_PACKAGED_APP`). These include *the bundled terminal engine starts a real PTY* and
  *closing terminals releases every PTY the app opened*, which is node-pty 1.2.0-beta.15's
  first run in the shipped app, under the hardened runtime and library validation.
- The protected `Release` workflow ran end to end on rehearsal tag `v0.0.5-rc.3`
  ([run 37140161875](https://github.com/TypeSafeAI/modex/actions/runs/37140161875)), behind
  the `release-signing` reviewer:
  - The tag signature verified.
  - The identity was imported into the job's own keychain.
  - The build was signed with the same leaf and notarized. The app and DMG were both accepted.
  - The packaged e2e passed (58/58, before #51 landed).
  - The artifacts were attached to a draft.
  - The keychain was deleted.
  - rc.1 and rc.2 failed on findings 3 and 4, before anything was built.

The published v0.0.5 artifacts come from the same workflow on the signed `v0.0.5` tag. Their
checksums, a local re-verification of the downloaded files, and the CI logs are attached to the
release as `verification-v0.0.5.txt`.

Reproduce the source checks from a worktree:

```sh
npm run build && npm test && npm run typecheck
npm run test:e2e
```

Build, sign, notarize and exercise the actual bundle (credentials in `.env.release`, see
[release-signing.md](../release-signing.md)):

```sh
scripts/release-mac.sh
MODEX_PACKAGED_APP="$PWD/apps/desktop/release/mac-arm64/Modex.app/Contents/MacOS/Modex" npm run test:e2e
```

Check a downloaded release:

```sh
shasum -a 256 -c SHA256SUMS.txt
spctl -a -vv -t open --context context:primary-signature Modex-0.0.5-arm64.dmg
xcrun stapler validate Modex-0.0.5-arm64.dmg
```

## Proof limits

Offline scripted CLI tests do not establish live-provider execution, paid-model behaviour, or
human VoiceOver acceptance. Gatekeeper was exercised with `spctl` and `stapler` on the build
machine and on downloaded copies, not on a freshly installed Mac. The app icon was checked as
rendered PNGs and byte-for-byte in the bundle, not in a Dock on light and dark wallpapers. The
release ships no auto-update and no Windows or Linux installers.
