# v0.3.0 release review

Desktop v0.3.0 ships native conversation fidelity: each turn is laid out from the CLIs' own typed
items, with truthful outcomes, evidence, plans and task records, approvals and questions answered
once, and a truthful Claude Stop. It also makes macOS updates install over the air, renders replies
as full Markdown and lets a project move to a new workspace from the chat sidebar. Val asked for
0.3.0 on 2026-10-19. iPhone Companion 0.3.0 (8) is cut from the same tag.

This preparation starts from protected `main` at `de856e0e9e33e09fd0e2f1e19e7ee4d0ba98b31e` (#318).
It changes the desktop and Companion versions, the release records, and the release identity check
so a `v<version>-rc.<N>` rehearsal tag runs the workflow again.

## Candidate behavior and compatibility

- **Updates.** v0.2.0 still needs one **Download update** click to reach v0.3.0, then **Restart to
  update**. From v0.3.0 on, a check downloads and verifies a newer release in the background, and an
  update nobody restarted into installs the next time Modex quits. Windows and Linux still install
  by hand. [Download and restart](../update-recovery.md#download-and-restart).
- **Transcripts.** Old transcripts read unchanged, with no invented provenance. New turns carry
  origin, phase, reasoning and outcome.
- **The event journal stays opt-in** (`MODEX_EVENT_JOURNAL=1`). Its schema is additive: a v0.2.0
  journal keeps its id. Downgrading keeps the file readable, but v0.2.0's phone mapping sends the new
  `plan` and `question` kinds as `null` and the phone rejects that snapshot. Deleting `events.sqlite`
  is always a safe rollback. [Compatibility and rollback](../event-journal.md#compatibility-and-rollback).
- **Older clients.** A paired desktop from before CF-3, such as TestFlight Store 0.0.8, gets a
  question or a plan as a notice it can read. The Mac sends the phone a question as text to answer
  on the Mac, so Companion 0.2.0 (7) needs no update for it. Companion 0.3.0 (8)'s only change is
  #318: it reads the thread again when the Mac refuses its answer.
- **Codex questions** (`item/tool/requestUserInput`) are experimental in codex-cli 0.163.0 and
  covered by scripted fixtures only.
- **Platforms.** macOS arm64 is Developer ID signed (Soul Protocol LLC) and notarized by the Release
  workflow. Windows and Linux candidates are built and checked the same way as v0.2.0's. Whether
  they are published is decided at publication.

## Hosted rehearsal

#317 changed the hosted native updater scenarios: they no longer click Download, and instead wait
for the automatic download of the tampered archive. That path had never run on a hosted Mac, so the
Release workflow was rehearsed on this branch before the real tag.

- The identity check required the tag to equal `v<package version>` since #186, which refused
  `-rc.N` rehearsal tags. This branch accepts `v<version>-rc.<N>` (N from 1, no leading zero) for
  the checked-out package version, with tests and
  [Rehearsing with an rc tag](../release-signing.md#rehearsing-with-an-rc-tag).
- The signed tag `v0.3.0-rc.1` on `96da81e6` passed
  [release run 39341997306](https://github.com/TypeSafeAI/modex/actions/runs/39341997306) on
  2026-10-19 in 41 minutes. Every job passed:
  - signing, notarization and stapling, then the packaged E2E;
  - the three signed native updater scenarios;
  - the Windows and Linux installer checks;
  - attaching the candidates to a draft.
- In each native scenario the transport log shows the release check, then the corrupt candidate
  archive fetched about a second later with no click, refused before native admission. The retry
  fetched the real archive.
  - **Upgrade:** Squirrel replaced the app and relaunched it as 0.3.0, with an exact-version
    installed receipt and the drafts kept.
  - **Native failure** and **interrupted download:** saved drafts survived and the manual
    reinstall path passed.
- The rc draft and both copies of the tag were deleted afterwards. v0.2.0 stayed the latest release.
- `main` then gained #318 (the iPhone Companion and docs) and #332 (a live-smoke spec that runs
  only on request, and its review). Neither changes the desktop app.

Install on quit is not exercised by the native scenarios, which still use **Restart to update**.
The fixture E2E covers it: the quit stages the update once and Modex does not relaunch.

## Release gates

1. Land this preparation through the guard, then sign tag `v0.3.0` on its squash (Val's go-ahead).
2. The Release workflow, after `release-signing` approval:
   - signs, notarizes and staples the app and DMG, then runs the packaged E2E;
   - runs the three hosted native updater scenarios and the Windows and Linux checks;
   - attaches the candidates to a draft.
3. Download the draft's assets and verify them independently:
   - `shasum -c`, the codesign leaf, `spctl` for the app and the DMG, and `stapler`;
   - the packaged E2E against the downloaded app.
4. Publish, then check `releases/latest` with the updater parser shipped in v0.2.0.
5. Upgrade the release Mac's v0.2.0 through its own banner (one Download click) with an unsent draft
   open. Record the `app/update-recovery.json` attempt, the sha512 against the published ZIP, the
   relaunch, About and the draft.
6. iPhone Companion 0.3.0 (8) from the same tag. Val is needed at the Mac for 1Password:
   - `op run --env-file=.env.release -- apps/ios/ModexCompanion/Scripts/release-testflight.sh`;
   - What to Test, the External group and beta review.
