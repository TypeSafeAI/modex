## Candidate behavior and compatibility

- Interactive Canvas retains HTML, SVG, and Markdown previews, file refresh, full view,
  and browser isolation from #164.
- The updater from #181 verifies downloads and the publisher, reports progress, and
  coordinates restart with active turns and unsaved work. Schema-2 drafts preserve text,
  attachments, pending originals, and uncertain native-update state. Unknown or corrupt
  recovery data is preserved; restart does not silently resend a pending message.
- Native Windows x64 NSIS and Linux x64 AppImage/Debian installers use the platform CLI,
  PTY, and encrypted-storage paths from #173. Windows signing is deferred. Windows and
  Linux updates remain manual.

If you run published v0.0.11 or earlier, install the first updater-enabled release
manually. Automatic installation applies to subsequent supported packaged-Mac updates
after signed native acceptance. The private `0.0.0` upgrade fixture uses the same source
as its candidate; it does not prove migration from a published historical build.

The planned draft contains five installers, `SHA256SUMS.txt`, and
`RELEASE-MANIFEST.json`. The [release workflow](../release-signing.md#cutting-a-release)
binds their bytes to the exact signed tag, source, run, and native reports. It excludes
private fixtures, refuses existing public releases or populated drafts, and does not
publish automatically.

## Windows test cleanup correction

[Native run 38380261716](https://github.com/TypeSafeAI/modex/actions/runs/38380261716)
at `51bedae` passed Linux but failed two Windows natural-exit cases in their cleanup
hooks: `spawnSync powershell.exe ETIMEDOUT`. The test bodies had passed their process-exit
assertions, then unconditionally invoked the independent emergency-cleanup script, which
exceeded its eight-second bound. The reason for that PowerShell delay is unproven.

The correction calls emergency cleanup only if the test has not completed its independent
exit assertions. Failed or incomplete cases still invoke the same ownership-checking
fallback; a fallback error still fails and preserves the fixture. CLI heartbeat assertions,
PTY cleanup receipts, PID absence, and resource-release checks remain intact. The
interactive PTY case additionally requires the recorded supervisor PID to disappear.
No application code or cleanup timeout changes.

A local hook harness reproduces the original timeout path and passes the corrected
verified-exit, incomplete-exit, and failed-fallback cases. This is control-flow regression
coverage, not native Windows acceptance.

The [next native run](https://github.com/TypeSafeAI/modex/actions/runs/38382398758)
at `b360c73` passed both originally failing cases and the stronger interactive check.
Windows passed 15 of 16 cases, then failed fixture removal with `EPERM` in the
supervisor-failure test. That path expected the cleanup rejection but did not wait for
PTY exit before removing the fixture; the promise can reject before output and console
closure finish. It now waits for the existing PTY exit event before declaring cleanup
verified. An actual-source ordering harness fails on the earlier block and passes with
the wait; the earlier fallback regression still passes.

[Native run 38384241789](https://github.com/TypeSafeAI/modex/actions/runs/38384241789)

## Release gates

1. Land the verified v0.0.12 preparation through a signed commit, review, current-head
   checks, and protected squash. Select that exact source for the signed tag review.
2. Obtain the required tag approval and `release-signing` environment review. Run
   signing, notarization, stapling, and packaged E2E on GitHub-hosted macOS.
3. Pass native upgrade, native download failure, and interrupted-download scenarios on
   three separate hosted macOS runners using the exact signed source and candidate ZIPs.
4. Run Windows/Linux jobs on that same tagged source. Verify their installer manifests,
   installed-app reports, and candidate hashes. Current reports retain
   `installerAcceptance: pending`; successful smoke checks do not establish authenticated
   Claude/Codex account operation, KWallet6, or a full graphical/PAM login session.
   Complete or explicitly disposition these checks during release review.
5. Independently verify the draft downloads, checksums, source/version/run identity,
   macOS signatures, Gatekeeper, stapled tickets, and native receipts. Record remaining
   limits and obtain publication approval before publishing; then verify public assets.

No signed tag, signing approval, native macOS updater run, draft upload, or publication
is established by this preparation. Physical iPhone and human VoiceOver acceptance
remain separate tracks.
