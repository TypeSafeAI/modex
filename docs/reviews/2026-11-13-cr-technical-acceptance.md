## Native resizing and restoration

The probes used Electron 44.4.5, Chromium 152.0.7977.130 and embedded Node 24.21.0 on macOS arm64. Each used a new private `MODEX_HOME`, verified the matching Electron userData directory, and redirected only window `show` to `showInactive`; production window creation, renderer, IPC, layout and window-state persistence stayed intact. Only the probe’s own window was moved or quit. Sampled native focus remained false.

1. At a 1440×900 native window, the real split divider began at 512 px, moved to 544 with the keyboard and to 524 with a pointer drag. The saved non-sensitive layout preference recorded 524.
2. A full quit/relaunch restored the 1440×900 window at its saved coordinates and the 524 px split preference.
3. A controlled private saved-window record located far outside every connected display recovered to a visible, bounded 1380×880 window. This is unavailable-coordinate recovery, not a physical monitor unplug test.
4. A private saved size of 200×100 was clamped to the native 900×600 minimum. The split folded to one active pane; both tabs and nine primary controls remained inside the viewport. Tree folding depends on the active pane width, so the checklist no longer assumes every 900 px window hides the tree.
5. With three real displays connected, the probe moved only its own window onto display id 1 at `{x:-1678,y:352,width:1300,height:800}`. A full quit/relaunch restored those exact second-display bounds and the 524 px split preference. No physical display was disconnected or reconfigured.

All six observed parent Electron PIDs were absent after the runs; this does not assert an exhaustive descendant audit. There were zero recorded GitHub mutations and no provider turns.
